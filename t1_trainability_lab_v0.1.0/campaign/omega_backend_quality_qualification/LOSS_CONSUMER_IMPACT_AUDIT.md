# OMEGA loss-contract consumer impact audit

**Contract being introduced:** `R1_MASKED_TOKEN_MEAN_V1` — `0.5*CE_valid_token_mean + 0.5*KL_teacher||student_valid_token_mean`, `tau=2`, `tau²` once.  
**Historical helper audited:** the actually loaded `omega_teacher_logit_cache.run_omega_teacher_logit_cache.distillation_loss`, file SHA-256 `ce025569ea1f3788c25f25d36afc4ae0a053a71698786983b95bb0689074fa1a`, last file commit `2c55aca99fa17f7d8aeec35ec9dd237995ba6adf`.

For full-valid `[B,L,V]` logits, the helper's CE is flattened and averaged over `B*L`, but its KL is `batchmean` on the 3-D tensor: `sum_(b,l,v) KL / B`. R1 instead sums over vocabulary per token, then divides by `N_valid`. With all tokens valid, KL ratio is exactly `L`; at `L=256`, old mixture is `0.5*CE_token + 128*KL_R1`, not `256×` the entire loss. This changes relative gradient contributions. The new canonical callable applies after either backend forward, so both arms share one implementation.
