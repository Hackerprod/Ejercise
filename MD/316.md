Q1 — Sí: CORRECTNESS_INVALID

MD/312 fue explícito: los checks full-size debían compararse contra el oracle escalar Q4 con las tolerancias KQ congeladas. El KQ congelado define:

Plain text
max_abs <= 1e-5
AND
max_rel <= 1e-4

con el relativo respecto a max(|ref|,1e-12).

Por tanto:

Plain text
V2-1c:
    COMPANION_BINDING_PREFLIGHT = PASS
    CORE_SELECTION_PREFLIGHT    = PASS
    CORRECTNESS_PREFLIGHT       = FAIL
    terminal = INVALID_PREFLIGHT
    72_CELL_SWEEP = NOT_RUN
    RESIDENCY_VERDICT = NONE

No reinterpretamos ese criterio después de haber visto los fallos.

Q2 — No se enmienda V2-1c

No autorizo relajar/modificar el comparator dentro de V2-1c. Eso sería post-hoc.

Sí considero que el criterio descubierto es mal condicionado cerca de cero y merece una unidad nueva, pero V2-1c queda cerrado tal cual.

El EXE congelado, binding y v_i siguen siendo evidencia válida de sus respectivos preflights; no quedan invalidados por el FAIL posterior.

Q3 — Oracle aplicable a V2-1c

Para V2-1c, el oracle vinculante sigue siendo el escalar exacto ya especificado (std::exp/división), no uno adaptado a exp_approx/rcp.

Los gates congelados aplicaban a:

Plain text
full-size:
    d512/d640 × m{1,4,8,16} × K1

toy recurrence:
    K{1,4,8}

No añado retrospectivamente full-size K8. Los K4 full-size realizados son diagnósticos adicionales.

Q4 — No repetir nada dentro de V2-1c
Plain text
anchors        = preserved PASS
binding seal   = preserved
v_i seal       = preserved
correctness    = preserved FAIL
timing sweep   = forbidden

No repetir preflight con otro criterio bajo el mismo identificador.
