Decisión de re-baseline
1. V2-1c no se toca

Sí: V2-1c se termina exactamente como está preregistrado. Su pregunta queda:

residencia d512/m4 con 4 P-cores en la i7 bajo el protocolo heredado.

No se cambia a 8P ni 24T en vuelo.

2. Después de V2-1c, OMEGA deja de estar atado al Ryzen

Ordeno un re-baseline explícito:

Plain text
OMEGA_HARDWARE_BASELINE_V3.md

Nueva jerarquía:

Plain text
PRIMARY_RESEARCH_PLATFORM:
    i7-13700F + GTX 1650 SUPER

PRIMARY_CPU_PHYSICAL_PROFILE:
    8 P-cores / 8 threads
    1 thread per physical P-core

THROUGHPUT_PROFILES:
    8P/16T
    8P + 8E = full 24 logical threads

LEGACY_DEPLOYMENT_PROFILE:
    Ryzen AI 5 330
    4 physical cores

No usaría 24T como gate primario de residencia: mezcla P/E/SMT y complica causalidad. Sí debe usarse para throughput real del sistema.

El Ryzen queda perfectamente válido como objetivo futuro de despliegue, no como plataforma que gobierna toda la investigación.

3. Qué queda obsoleto/re-derivado de Conversacion.md

No queda obsoleta la arquitectura:

Plain text
shared recurrent core
K-flex
matrix workspace m
16d² core
external memory later
R4 vs U4

Sí quedan hardware-specific y deben dejar de tratarse como universales:

Plain text
"4 physical threads"              → Ryzen profile only
d512 = L2 candidate               → Ryzen-specific
d640 = L2 frontier                → Ryzen-specific
8 MB L3 assumptions               → Ryzen-specific
rho <= 0.50 universal gate        → historical/Ryzen-derived gate
fixed cache knees                 → host-specific

En la i7 hay que re-derivar H0/H1 y las rodillas desde sus 2 MiB L2/P-core y ~30 MiB LLC.

Para la workstation, además de d512/d640, el sweep físico debe incluir tamaños que realmente crucen sus cachés; aproximadamente d1024–d2048 merece exploración. No voy a llamar d512 “frontera L2” en esta máquina.

La tesis tampoco cambia a simplemente «eficiente por FLOP». La formulación correcta pasa a ser:

La recurrencia/sharing es la tesis arquitectónica general; la residencia en caché es una hipótesis de despliegue dependiente del host.

Eso evita que un FAIL de cache en una CPU mate una arquitectura que puede seguir teniendo valor en GPU u otros CPUs.
