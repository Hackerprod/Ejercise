Hay una ventaja importante: los checkpoints son cada 500 updates y 500 es par. Si hemos completado 500 updates, el siguiente índice es 500, luego:

500mod2=0

por lo que el siguiente update comienza en window 0, donde el estado recurrente se reinicia. Eso hace esas fronteras particularmente limpias para recuperación: no necesitamos intentar reconstruir un workspace persistente a mitad de una pareja causal.

último checkpoint válido = 12,000
updates 12,001..12,347 del segmento roto = evidencia preservada,

resume explícito desde 12,000
nuevo segment_id
siguiente update canónico = 12,000 / window 0
