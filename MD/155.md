## 4. Verificar el entrypoint real, no una regeneración forzada de claves

El script verify-image.sh actual sobrescribe el entrypoint con Bash, borra las claves y ejecuta ssh-keygen -A manualmente. Eso puede demostrar que dos generaciones producen claves distintas, pero no verifica que el arranque normal de la imagen tenga ese comportamiento ni detectaría por sí solo claves horneadas que acaba de borrar.

Ajustarlo dentro de esta unidad para comprobar dos propiedades separadas:

- **Imagen sin arrancar**: no contiene claves privadas de host SSH.
- **Arranque normal**: dos contenedores nuevos, iniciados con el entrypoint real y una clave pública de prueba, generan fingerprints distintos y levantan SSH sin iniciar entrenamiento.

La prueba no debe borrar claves para hacer pasar la primera condición. Para la segunda, tampoco debe reemplazar el entrypoint que pretende verificar.

Realizar el acceso de prueba exclusivamente por loopback y un puerto alto disponible, sin tocar el SSH del VPS en el puerto 22. Usar credenciales desechables de la prueba, no copiar claves privadas del usuario a la imagen.

Comprobar además que un directorio temporal montado como /workspace deja accesible el código de /opt/omega y que /workspace/omega sigue siendo un directorio dentro de ese montaje. No montar ni modificar el volumen real q4t3-vol para probar esto.

Estas correcciones no necesitan otra autorización ni otro design-audit: forman parte de verificar materialmente la imagen.
