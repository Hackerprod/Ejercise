4. Ejecución científica: no convertirla en otro shadow test

Cada backend avanza su propia trayectoria. No se restauran los pesos nativos desde PyTorch ni se exige allclose entre todos sus estados después de cada update. Precisamente estamos cualificando las consecuencias de esas trayectorias independientes.

Se mantienen activos los controles de integridad:

Finitud de pérdida, gradientes y parámetros.

Identidad de receta, DLL, datos y pérdida.

Schedule causal, tokens válidos y número de pasos AdamW.

Integridad de checkpoints y ledger.

Registrar CE, KL, total, norma pre-clipping y coeficiente aplicado. No cambiar el clipping si interviene con frecuencia ni ajustar el LR al observar las curvas.

Guardar checkpoint y evaluar en:

0, 500, 1000, 1500 y 2000 updates completados

El endpoint sigue siendo 2.000, aunque una validación intermedia resulte mejor. No se selecciona retrospectivamente el mínimo.

Ante una interrupción operativa, se puede reanudar desde el último checkpoint propio verificado mediante el mecanismo certificado. Los updates del intento descartado no cuentan como progreso canónico. Nunca se cambia de backend ni se reinicia una seed para obtener una curva más favorable.
