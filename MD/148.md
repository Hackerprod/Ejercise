6. Dos detalles del código R1 que el runner debe manejar
Dispositivo del estado inicial

Actualmente:

Python
Run
def initial_state(self, batch_size):
    return torch.zeros(batch_size, self.slots, self.dimension)

crea el estado sin especificar dispositivo. Para ejecutar en GPU, el runner debe crear el cero inicial en el mismo dispositivo y dtype del estudiante, por ejemplo a partir de embedding.weight.new_zeros(...). Es una adaptación de dispositivo, no una modificación arquitectónica.

Continuidad entre ventanas

forward_tokens() reinicia el estado al comenzar cada llamada. La prueba sintética de continuidad funciona porque conserva manualmente el estado y continúa mediante forward_token().

Por ello, el trainer debe manejar explícitamente una interfaz equivalente a:

forward_window(tokens, previous_state, valid_mask, reset_mask)
    → logits, next_state

sin cambiar las operaciones de R1.

Entre ventanas contiguas del mismo documento, conservar el valor de S y cortar el grafo. Al cambiar de documento, reiniciar el estado. El padding no debe actualizarlo y su pérdida debe quedar enmascarada.

Comprobar la equivalencia entre procesamiento continuo y ventanas con pesos fijos. No exigir esa igualdad cuando se ejecuta un update entre ventanas: en ese caso los pesos ya no son los mismos.
