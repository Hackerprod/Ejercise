## 2. El cero de `representation_sensitivity_count` es consecuencia de una condición equivocada

En `layer_b()` aparece:

```python
diagnostic_representation_sensitivity = (
    canonical_correct
    and not oracle_final_success
)
```

Eso comprueba si falla **el ejecutor con acción oráculo**, no si el controlador cambia de una decisión canónica correcta a una decisión contextual incorrecta. Como `oracle_final_success` es verdadero en todos los casos, ese contador necesariamente queda en cero.

La comparación que queríamos medir es:

```python
diagnostic_representation_sensitivity = (
    canonical_correct
    and not decision_correct
)
```

La diferencia es esencial:

```text
El ejecutor puede operar correctamente sobre R.
El controlador puede, aun así, interpretar mal ese mismo R.
```

Los ocho adicionales **no demuestran que la memoria haya recuperado una fila incorrecta ni que la ALU falle**. No atribuiría todavía esa sensibilidad a una magnitud específica de ruido o a una zona concreta de logits sin guardar las trazas correspondientes. Pero **ya no es válido decir que la representación recuperada quedó completamente descartada como factor de la decisión**.

## 4. Antes de replicar: corregir el resumen, no los pesos

Haría un ajuste acotado al evaluador. La tabla de comparación debe distinguir:

| Canónico   | Contextual | Interpretación de la comparación |
| ---------- | ---------- | -------------------------------- |
| Correcto   | Correcto   | Acuerdo correcto                 |
| Incorrecto | Incorrecto | Error compartido                 |
| Correcto   | Incorrecto | Regresión contextual             |
| Incorrecto | Correcto   | Recuperación contextual          |

La partición de los errores de decisión debe satisfacer:

```python
decision_error_count = sum(
    not record["decision_correct"]
    for record in records
)

shared_error_count = sum(
    not record["canonical_correct"]
    and not record["decision_correct"]
    for record in records
)

contextual_regression_count = sum(
    record["canonical_correct"]
    and not record["decision_correct"]
    for record in records
)

assert decision_error_count == (
    shared_error_count + contextual_regression_count
)
```

Esto es una tabla de coherencia entre dos formas de entrada. Para atribuir **primera causa** dentro de una trayectoria, mantener además la condición `aligned`: un error previo de navegación no debe convertirse después en un fallo independiente de CTRL-2.

Un fixture donde el controlador canónico acierta, el contextual falla y el ejecutor oráculo acierta debe incrementar la regresión contextual. Otro donde la decisión contextual es correcta pero falla su ejecución debe incrementar la categoría de ejecución, no la sensibilidad del comparador.

La corrección agregada puede calcularse desde las tablas ya guardadas, sin entrenar nada. Añadiría también un listado derivado de **todas las parejas contextuales con fallos**, no solo de `(15,13)`.

El evaluador actual guarda la tabla canónica y los agregados por pareja, pero no exporta los 64,000 registros contextuales individuales. Para conservar las ocho discrepancias con detalle, puede repetirse únicamente la evaluación congelada y guardar los casos fallidos con episodio, pareja, predicciones y logits. **Eso es completar la evidencia, no una nueva búsqueda de hipótesis.**
