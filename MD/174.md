1. Integración exacta: clase nueva, núcleo F intacto

Sí: quiero una clase nueva, conceptualmente:

OmegaCoreLMFastER32

La mejor forma de implementarla es reutilizar directamente OmegaCoreLMFast, no copiar de nuevo el recurrent core.

F ya contiene la implementación validada del prelude, QKV fusionado, SDPA, MLP, RMSNorm, depth modulation, gates y readout projection. Su única dependencia léxica directa es self.embedding(tokens) en la entrada y self.embedding.weight para los logits.

Por tanto, el diseño preferido es:

OmegaCoreLMFastER32(OmegaCoreLMFast)
    │
    ├── hereda SIN CAMBIOS:
    │     prelude
    │     prelude_norm_weight
    │     blocks / FastWorkspaceUpdateBlock
    │     depth_embedding
    │     gate_logits
    │     readout_norm_weight
    │     output_projection
    │     _round_constants()
    │     recur_states()
    │     project()
    │     forward_window()
    │
    └── sustituye únicamente:
          embedding.weight [V,D]
             ↓
          FactorizedVocabulary:
              C [V,32]
              U [32,D]

          y override:
              logits_from_projected()
FactorizedVocabulary

Debe ser un nn.Module con:

C: Parameter[V, 32]
U: Parameter[32, 128]
implementation = explicit | efficient

y forward(tokens):

Python
Run
explicit:
    E = C @ U
    return embedding(tokens, E)

efficient:
    return C[tokens] @ U

Así el recur_states() heredado de F puede seguir llamando simplemente:

Python
Run
self.embedding(tokens)

sin duplicar el recurrent core.

Sólo se sobreescribe el readout:

Python
Run
explicit:
    E = C @ U
    logits = projected @ E.T / sqrt(128)

efficient:
    logits = (projected @ U.T) @ C.T / sqrt(128)

No debe existir ningún Parameter[V,D] en ER32.

Eso mantiene el core de F literalmente reutilizado, en vez de crear una tercera copia del algoritmo recurrente.
