4. Qué debe responder el informe

No fijaría de antemano que “ahora toca GELU vectorial” o “ahora toca FMA”. Son posibilidades conocidas, pero el perfil debe decidir si tienen suficiente peso en el programa actual.

El informe debe separar forward y backward por caller real, no exclusivamente por símbolo hoja. gelu, state_prelude_write u otra función compartida puede participar en ambos caminos. Y no se debe excluir código de biblioteca llamado desde el recurrente: las herramientas de Microsoft permiten mostrar esas llamadas externas, cuya atribución mejora con símbolos correspondientes.

La tabla final debe contener operación/dirección, función o región, peso exclusivo de muestras, caller y correspondencia con el source. Si una parte grande queda dentro de una función inlineada, hay que localizar las líneas o instrucciones relevantes antes de asignarle una causa.

Tres límites de interpretación

Los porcentajes viejos no se reciclan. Ni el 46.75% de backward anterior ni las ablaciones de RMSNorm describen automáticamente este baseline.

Peso de muestras no equivale a wall-clock del update. Se mantienen separados los conteos enteros de muestras, sus pesos y el tiempo transcurrido. WPA define esos campos de manera distinta. 
Microsoft Learn

Dos porcentajes iguales en programas distintos no significan tiempos iguales. La comparación debe conservar las magnitudes absolutas disponibles y el contexto de uso de CPU. No basta con decir “GELU es el 20% en ambos”.

Para distinguir cómputo de espera, utilizar los datos de estados de threads o fallos de página sólo cuando estén capturados. No atribuir una diferencia a caché, scheduling o ancho de banda por descarte. 
Microsoft Learn
