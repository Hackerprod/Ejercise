Intervención exacta

Mantener la reconstrucción, tokenización, deduplicación y orden de documentos actuales.

Para cada documento elegible, en lugar de conservar únicamente:

Plain text
tokens[0:513]

crear todos sus bloques completos de 513 tokens usando stride 512:

Plain text
chunk 0: tokens[0:513]
chunk 1: tokens[512:1025]
chunk 2: tokens[1024:1537]
...

Esto es mejor que stride 513 porque cada chunk conserva un token de contexto compartido, pero ningún target de entrenamiento se duplica entre chunks consecutivos.

Fundamentalmente:

Plain text
W0 = primeros 256 targets del chunk
W1 = siguientes 256 targets

W0 → state → detach → W1

FIN DEL CHUNK:
    reset completo

No transportar estado entre chunks. No cruzar el detach de 256 tokens.

Así esta unidad cambia exclusivamente cobertura del corpus, no el horizonte de crédito temporal. El problema >256/>512 queda para otra unidad.

Orden del nuevo corpus

No usaría orden documento0/chunk0, documento0/chunk1, ..., porque podría meter varios fragmentos del mismo artículo en un mismo batch.

Construiría el pool por profundidad de chunk:

Plain text
todos los chunk0 en orden histórico de documentos
todos los chunk1 que existan
todos los chunk2 que existan
...

Esto tiene una propiedad excelente: los primeros 602 chunks preservan exactamente la población histórica de primeros fragmentos, y luego aparecen los textos adicionales.
