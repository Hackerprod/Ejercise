## Qué significa el recorrido completo

La secuencia experimental ahora es especialmente valiosa porque **cada fallo cambió una sola interpretación**:

```text
v0
│
├─ fallo: posición + longitud + AND + recencia confundidos
│
R1
│
├─ arregla estructura
├─ descubre NOOP VALUE_0 como shortcut
│
R1.1
│
├─ elimina también ese confound
├─ A falla por falta de factorization inductiva
├─ B compone parcialmente
│
B-ALG
│
├─ z_F + z_A → PASS exhaustivo
├─ significados atómicos correctos
└─ culpable: agregación secuencial
│
R2
│
└─ clause-wise encoding + suma
      → PASS exhaustivo ambos órdenes
```

Por eso el resultado de R2 es más fuerte que simplemente «otra arquitectura dio 100%».

**La modificación que solucionó el problema fue predicha por el diagnóstico causal anterior.** No fue un barrido de arquitecturas hasta encontrar una que funcionara.

La afirmación que firmaría es:

> **En este dominio controlado, un encoder compartido aprende representaciones funcionales de instrucciones atómicas que pueden componerse mediante agregación aditiva para ejecutar correctamente una combinación semántica nunca observada durante entrenamiento, incluyendo interacción secuencial entre las reglas.**

No significa todavía lenguaje natural general. El sistema recibe tokenización y segmentación de cláusulas explícitas, y la composición está favorecida estructuralmente por una suma conmutativa. Pero ahora sabemos algo importante: **la representación lingüística atómica y el controlador pueden desacoplarse de forma modular y composable.**

# Siguiente fase que propondría: `T2-I1 — lexical abstraction`

No eliminaría todavía también el split por `AND`. Eso mezclaría dos preguntas nuevas.

Ahora probaría si **la misma semántica puede expresarse mediante distintas superficies léxicas** mientras mantenemos congelado:

```text
CTRL-7
runtime
scorer
Q
additive clause aggregation
```

Por ejemplo, introducir dos nombres para cada operador:

```text
FLOOR:
AT_LEAST VALUE_n
MINIMUM VALUE_n

AVOID:
AVOID VALUE_n
EXCLUDE VALUE_n
```

No asumir que palabras nunca vistas tienen significado. Cada alias debe aprenderse **atómicamente**.

Training:

```text
AT_LEAST n
MINIMUM n

AVOID f
EXCLUDE f

+ todas sus formas con NOOP
```

pero nunca ninguna combinación de dos operadores reales.

Held-out sería el producto cruzado:

```text
AT_LEAST L AND AVOID F
AT_LEAST L AND EXCLUDE F
MINIMUM L AND AVOID F
MINIMUM L AND EXCLUDE F
```

y los cuatro con orden invertido.

La pregunta pasa de:

> «¿puede sumar FLOOR y AVOID?»

a:

> **«¿aprendió una semántica estable de FLOOR/AVOID independientemente de qué superficie lexical la activa?»**

El gate fuerte sería que las ocho realizaciones produzcan la misma conducta en los `31,744` casos y en la batería real/interacción.

Si eso pasa, entonces **T2-I2** sí debería atacar el scaffold estructural más grande que queda: el `split on AND`, sustituyéndolo por detección/segmentación aprendida sin abandonar la composición por cláusulas.
